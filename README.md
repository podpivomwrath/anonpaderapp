# Монолит — текстовая RPG во ВКонтакте

Игра через сообщения сообщества VK и мини-приложение управления персонажем.
Сервер: Python 3.12+, vkbottle, aiohttp; PostgreSQL, SQLAlchemy async, Alembic;
Redis для дедупликации событий и временных боевых действий. Мини-приложение:
React, Vite, VKUI. Развёртывание: Docker Compose + Caddy на одном VPS.

## Игровые возможности

- Сюжетное создание персонажа, три базовых класса, шесть подклассов и четыре региона.
- Карта, исследование, сюжетные и ежедневные задания, отдых и возрождение.
- Прокачка характеристик, экипировка, трофеи, заточка, расходники и маунты.
- Пресеты микробаффов и испытания; неготовые баффы явно помечены в контенте.
- Одиночный и групповой PvE, дуэли и массовый PvP, группы игроков.
- Трёхэтапный рейд «Кукольный театр» у Монолита, вход за ключ лидера.
- Премиум через промокоды, инструменты администратора и блокировки игроков.
- Мини-приложение: персонаж, инвентарь, задания, карта, админка.
  Биржа в интерфейсе пока заглушка; расчёт дилерской биржи есть в игровом ядре.

## Архитектура

- `main.py` — запуск бота, HTTP API и планировщиков.
- `bot/` — обработчики событий, кнопки, авторизация мини-приложения.
- `bot/activity.py` — резервирование участников при переходах между активностями.
- `bot/battle_keyboard.py` — определение боя и клавиатура всех боевых режимов.
- `game/` — формулы, движки боёв, экономика и правила мира.
- `services/` — операции с персонажем и прогрессом, общие для чата и HTTP.
- `models/`, `migrations/` — схема PostgreSQL и последовательные миграции.
- `content/` — JSON-тексты, монстры, предметы, задания и баланс контента.
- `miniapp/` — интерфейс персонажа; см. [инструкцию](miniapp/README.md).
- `tests/` — модульные, HTTP и дополнительные PostgreSQL-проверки.

Дуэли используют последовательные ходы. Тиковый движок разрешает общие ходы
PvE/PvP и работает отдельными экземплярами для разных режимов. Действия и
таймеры относятся к конкретному экземпляру боя и номеру хода.

## Локальный запуск

```sh
docker compose up -d
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
# Скопировать .env.example в .env и заполнить настройки VK
alembic upgrade head
python main.py
```

`BOT_MODE=polling` позволяет работать без публичного webhook. Для callback
нужны `VK_TOKEN`, `VK_GROUP_ID`, `VK_CONFIRMATION_CODE`, `VK_SECRET` и публичный
адрес `/vk/callback`, зарегистрированный в настройках сообщества VK.
HTTP-сервер по умолчанию слушает порт 8080; `/health` — проверка доступности.

## Безопасный запуск тестов

```sh
python scripts/test_local.py -q
```

Этот запуск отключает загрузку `.env`, подставляет тестовые настройки и
блокирует внешние сетевые соединения. Обычные тесты используют SQLite в памяти.
Количество тестов выводит pytest; в документации оно намеренно не фиксируется.

Проверки конкуренции PostgreSQL запускаются дополнительно на ОТДЕЛЬНОЙ локальной
БД `pines_test`. Например:

```sh
docker run -d --name pines-test-pg -p 127.0.0.1:55439:5432 -e POSTGRES_USER=audit -e POSTGRES_PASSWORD=local-test -e POSTGRES_DB=pines_test postgres:16-alpine
# PowerShell:
$env:TEST_DATABASE_URL='postgresql+asyncpg://audit:local-test@127.0.0.1:55439/pines_test'
python scripts/test_local.py -q
```

Каждый PostgreSQL-тест создаёт и удаляет собственную случайную схему.
Без `TEST_DATABASE_URL` эти интеграционные тесты пропускаются. Рабочую БД
использовать нельзя; тесты проверяют имя БД и локальный адрес.

## Сохранение и восстановление

Персонажи, группы и рейдовые лобби хранятся в PostgreSQL. Боевые состояния
остаются в памяти одного процесса; горизонтальный запуск нескольких ботов
с одной БД не поддерживается.

При старте рейда ключ списывается в одной транзакции с записью `raid_runs`.
После перезапуска незавершённые рейды помечаются технически прерванными,
ключ возвращается лидеру ровно один раз, уже выданные награды сохраняются.
Компенсация может превысить обычный лимит выпадения ключей. Успешно законченные
рейды и поражения компенсации не получают. Продолжения с середины боя нет.
Это восстановление действует для запусков после миграции 0025; старые бои
без записи в журнале восстановить автоматически нельзя.

## Развёртывание

См. [DEPLOY.md](DEPLOY.md). Перед обновлением — резервная копия БД;
новые миграции применяются до запуска нового сервера. Удаление персонажей
через `scripts/wipe.py` не является частью обновления и на проде не применяется.
